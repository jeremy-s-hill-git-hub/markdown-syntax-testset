# 项目约束

本文件定义测试样本集的目标、交付边界、标注形态与写作规则。写测试文件或索引时必读。

## B1 项目目标

- 构建一套可直接在目标编辑器中打开、**肉眼目测**的 Markdown 样本集，用于判断编辑器对各类 Markdown 语法的支持情况。
- 覆盖面底线：**至少包括 CommonMark、GFM**。

### B1.1 实测范围

- **实测三个轴**：
  1. **规范方言** — CommonMark、GFM、Pandoc Markdown；
  2. **编辑器特性** — Mermaid 图表、GitHub Alerts、CriticMarkup 修订标记、自动目录 / WikiLinks；
  3. **其他方言独有语法** — MultiMarkdown、Markdown Extra、Kramdown 中尚未被上述三方言覆盖的部分。
- **去重约定**：脚注、定义列表、数学、引用、缩写、属性语法、高亮、智能标点、emoji 等已由 Pandoc 维度覆盖，其他方言**不重复测试**；CriticMarkup 只在 `03-editor-features/ef-critic.md` 出现一次，不在 MMD 节重测。
- **仅声明存在、不产出测试文件**：MDX、R Markdown。二者需 JS 编译或 knitr 执行环境，裸渲染测试无意义。该声明写在本 skill，**不写入 `markdown.index.md`**（B4 白名单只允许子文件链接与基础语法样例）；如需就近说明，可放在 `04-other-dialects/` 测试文件的开头说明文字中。

## B2 主要交付约束（硬性）

`markdown-syntax-testset/` 是**唯一内容目录**，同时是主要交付物——测试文件只存在这一份，不设工作副本。该目录内只允许存在三类内容：

| 允许 | 说明 |
| --- | --- |
| 测试文件 | 交付的 Markdown 语法测试文件本身，可有多个 |
| `markdown.index.md` | 用于且**只用于**索引这些测试文件 |
| 测试配套资源 | 测试用例必需的媒体文件（如 `media/placeholder.svg`），仅供测试引用 |

其它一切内容（参考资料、提示词、草稿、临时文件、笔记、脚本、日志、中间产物）**一律不得出现**。

- 因为没有工作副本，"交付前清理"即等同于**始终保持整洁**：任何时刻在该目录内新增文件都要先确认它属于上述三类。
- 素材、脚本、skill 包一律放在 `markdown-syntax-testset/` 之外的工作区目录（`_sources/`、`markdown-syntax-testing/`）。
- **检测时点**：交付前做一次确认性核对即可，正常情况下应当一次通过。

**推论**：`markdown/_sources/`（规范原文、素材、脚本、skill 各版本）属工作区产物，**始终位于该目录之外**，无需移出。

**推论**：agent 不得以「交付白名单」为由干预工作区其它目录；白名单只描述 `markdown-syntax-testset/` 的形态。

### B2.1 白名单的三处边界

1. **测试子目录** —— 目录本身算「测试文件的容器」，允许存在；其中只能放 `.md` 与配套资源。
2. **媒体文件** —— 测试用例引用的图片等算「测试配套资源」，允许存在；无引用的媒体视为残留。**媒体一律使用 SVG**（纯文本 XML）：本仓库不纳入二进制文件，`media/` 下不得出现 png、jpg 等位图。
3. **纯文本手册** —— 抓取所得纯文本可能丢失标记（如 `±` 兼作 `+`/`-`），不可用于判定扩展默认状态；以程序输出为准，见 `sources.md`。

## B3 整个交付物都是测试文件

- 交付内容的**全部文件**都是 Markdown 渲染测试的一部分。
- `markdown.index.md` 也不例外：它**本身就是一个基础测试用例**，同时声明其他用例的位置。
- 因此 `markdown.index.md` 不需要任何「豁免」——它就是测试文件之一。

## B4 `markdown.index.md` 的内容白名单

它兼作 README，但**只允许**承载以下两类内容：

1. **子文件的作用和链接** —— 说明每个子文件测什么，以及如何跳转过去。
2. **所采用的基础语法的样例（裸渲染）** —— 声明本文件用了哪些基础语法，并各自真实裸露地演示一次，参考 B4.1。

除此之外不放任何东西。

- 开发过程的提示词、资源文件等**不属于交付部分**，不得出现、也不必在索引中提及。
- 导航区必须包含一条**指向本文档锚点的对照链接**，用于区分「断链」与「不支持链接语法」。

**推论**：「前置自检说明」「使用说明」「进度」「参考内容登记」等均不属于上述两类，不得写入索引。

### B4.1 用例标注（双形态，不含 HTML）

- **默认形态**：纯文本标签行，独占一段，前后空行，行尾加**两个空格**产生硬换行，分两行书写：

  ```
  T:名称 | 源 规范+章节··
  预期 简述 | 流行度 A–D
  ```

  （`··` 表示两个空格，断点在「源」之后：第一行=身份，第二行=判据）
- **备用形态**：可见标题 `#### T:名称 | 源 ... | 预期 ...`（单行，不拆）
- **无编号**：`T:` 后直接接用例名称，项目内不设编号，用例以名称为标识；跨文件同名时以文件名区分。
- **选择规则**：
  - 一般用例 → 文本标签行；
  - 用例本身是 ATX / Setext 标题 → 必须用文本标签行；
  - 用例本身是段落 / 硬换行 / 软换行 → 必须用可见标题（因为标签行本身是段落，会与被测对象撞脸）；
  - 其余（列表、引用、表格等）→ 优先文本标签行。
- **禁止**：用 HTML 注释承载标注。HTML 支持本身是必测内容，作为**被测对象**出现是允许的。
- **理由**：两种形态恰好覆盖彼此死角——标题形态测不了标题，文本形态测不了段落。

## B5 「基础」的定义

- 整个项目对语法的**说明性文字**（写说明、做导航、做标注的那一层）一律使用**最基础且最简单的语法**。
- `markdown.index.md` 同样适用，不例外。
- 仅限 **CommonMark**（ATX 标题、段落、无序/有序列表、引用、分隔线、链接、行内代码、强调）。

**明确边界**：此要求**不**意味着让 index 使用全部 CommonMark 语法。index 只需用最基础的那几种，并裸渲染出来即可。

### B5.1 二重身份原则

**交付物同时是「说明」与「样例」。**

- 说明文字本身也在被渲染，因此它也必须遵守 B5 的基础语法约束。
- 说明文字可以、且应当**同时充当语法样例**——写「这是一个段落」的那段话，本身就是一个段落。
- 因此写作时不要只想着「讲清楚」，要同时想着「这段话演示了什么语法」。
- 当说明文字与被测对象可能混淆时，用 B4.1 的双形态把二者分开。

### B5.2 语言分工（硬性）

- **说明文字用中文**：章节标题、用例标签、讲解段落、判读提示。
- **示例文字用英文**：被测语法片段的内容本身。
- 目的是让读者一眼分清「哪句是讲解、哪段是被测内容」。

**唯一例外**：当**被测量对象本身就是中文**时，示例必须保留中文，否则测不到。这类用例在文件中需就近注明理由。已确认的例外清单：

| 用例 | 对象 |
| --- | --- |
| 中文与全角标点 | 中文标点渲染 |
| 反引号与星号在中文语境 | 中文与行内语法混排 |
| 全角空格 | 全角空格的缩进行为 |
| 从右到左文字 | RTL 文字方向 |
| 标识符生成算法 | 中文标题的锚点生成 |
| 东亚换行 | 中文之间的软换行 |

## B6 自我一致性要求

索引的「用了什么」与「演示了什么」必须严格对齐：

| 状况 | 判定 |
| --- | --- |
| 用了某语法却未演示 | 漏测 |
| 演示了某语法正文却未用 | 冗余 |
| 用了且演示了 | 合规 |

此为**自我一致性要求**，不是覆盖目标。

## B7 裸露原则

- 被测语法必须**裸露**，代码块包裹即视为未测试。
- 索引**不使用表格，也不测试表格**（表格属 GFM 扩展，在子文件中裸露测试）。
- **全部未闭合构造**（行内未闭合的强调、代码、链接、图片、行内 HTML，以及未闭合围栏、未闭合块级 HTML）一律放在文件末尾，防止吞噬后续内容。
- 同文件内多条未闭合用例按**吞噬范围递增**排列：行内未闭合在前（仅影响本段），吞到文件末尾的块级构造居中，未闭合围栏居最末；围栏之后不得有任何内容。
- 未闭合用例之间应避免共享同类定界符，例如未闭合反引号与反引号围栏同文件相邻时，宽松实现下可能互相匹配；无法避开时改用异类围栏（如波浪线）。
- **围栏冲突预警**：三个波浪线或三个反引号出现在**行首**即被当作围栏符。测试删除线、波浪线相关内容时，必须在行首前加文字，否则内容会被围栏吞掉。
- **标题层级保护**：被测对象是 H1 时会与文档标题冲突。可接受（测 H1 必须写 H1），但同一文件不应出现多个 H1；能降级时降级。
- **位置敏感语法必须在文件起点**：YAML 元数据块、传统标题块这类语法**只在文档最开头生效**，写在中间等于没测。遇到这类语法，直接把测试文件的前几行让给它；标签与说明文字放在其后。当前已按此处理：`pd-on.md` 的元数据块位于第 1–5 行；`od-other.md` 的 MMD 元数据头位于第 1 行起。

## B8 不记录原则

- **不写自检结果** —— 不给通过/失败记录位。
- **不写测试结果** —— 子文件不设「实际结果」「状态」位。
- **不做汇总** —— 不设文件登记表、用例对照表、覆盖度仪表盘、未覆盖清单。
- **不写历史** —— 不记录跨编辑器对比、多次测试记录。

样本集只提供「可看的语法」，不提供「记录」。

**文件夹编号原则（低优先级）**：按「使用量 / 基础性」升序编号——越基础、被越多上层语法包含者，使用量越大、编号越小；**扩展集不得先于其基础集**（故 GFM 不先于 CommonMark，Pandoc 不先于 GFM）。当前顺序 `00 → 04` 即按此原则。

**文件体量参考（低优先级）**：各测试文件行数宜适中、大致相当（约 100–150 行为参考），**不刻意充水或缩减**；`markdown.index.md` 不受此限。
