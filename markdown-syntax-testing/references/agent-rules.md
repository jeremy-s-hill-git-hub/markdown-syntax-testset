# Agent 行为约束

本文件定义执行本 skill 时的行为纪律。涉及停手、写入、验证、核验、安全与素材请求时必读。

## A0 开发规则

- 本 skill 处于开发阶段，agent 根据实际情况与用户需求进行，计划如有调整**提醒用户更新 skill**，提供新 skill 完整样例，向用户说明如何部署——**不要直接改写正在用的 skill 文件**。

## A1 停手规则

### A1.1 执行期停手（遇到错误）

- 遇到任何错误、异常、阻碍（**尤其是网页读取失败**）→ **立即停止生成**，向用户报告，由用户提供解决方案。
- **不自行尝试绕过**：不换 URL、不换镜像、不换工具、不猜测内容充数。
- 已尝试的路径与失败原因要如实列出，不掩盖。
- 工具调用出现意外（审批被取消、权限拒绝）→ 立即停止，及时止损，不重试。

### A1.2 思考期停手（发现冲突）

- **在思考阶段发现的冲突点，一律立即停止生成，交由用户决断。**
- 适用范围包括但不限于：
  - 用户前后指令互相矛盾；
  - 用户指令与既有约束/规范互相矛盾；
  - 项目约束内部互相矛盾；
  - 参考素材之间互相矛盾；
  - 同一需求存在两种以上合理解读且会导致不同产出。
- **停止的含义**：不继续生成正文内容，**仅输出冲突陈述**——说明冲突点是什么、涉及哪几处、各自指向什么结果、需要用户决断什么。
- **禁止行为**：
  - 不得自行选择其中一个解读继续执行；
  - 不得以「取折中」「两版都写」等方式回避决断；
  - 不得把冲突点埋在正文里轻描淡写地提一句就继续；
  - 不得等用户追问才说明。
- **判定标准**：只要「按 A 做」与「按 B 做」会产出不同结果，且 A、B 均有依据，即构成冲突，必须停手。
- 冲突陈述应**尽量短**，一屏内说清。

## A2 写入纪律

- 对**未明确写入**的内容不得擅自写入。
- **谋定而后动**：先确认再动手，不预设用户的决策。
- 区分三种层级，写入文档时不得混淆：
  1. **用户原话** — 直接记录；
  2. **由原话直接推导的结论** — 必须冠以「推论」；
  3. **agent 自己的建议** — 必须标注「非需求」，并单独成节。

## A3 阶段纪律

- **规划阶段**只出计划与需求确认，不产出交付文件。
- 未获准进入执行阶段前，不创建交付目录、不生成测试文件。

## A4 验证纪律

- 任何写入后必须**读回验证**，并给出证据（行数、字节数、`grep` 结果、记忆节点 id）。
- 不凭「我已经写了」下结论。
- 批量脚本改写后，必须用独立脚本复核结果（不能只信脚本自己的输出）。

## A5 事实核验

- 涉及规范内容的判断**必须查证**，不得仅凭记忆。
- **可执行程序优先于文档**：判断「某工具是否支持某语法」时，直接问程序本身（如
  `pandoc --list-extensions=markdown`），不要靠解析手册猜。
- 文档与程序冲突时，以**程序输出**为准，并记录该差异。
- 查证所需材料无法自行获取时，转 **A7 素材请求规则**。

## A6 安全性

- 涉及可能真实执行的用例（`<script>`、`onerror`、`javascript:` 链接等），必须先提示风险并给出操作规则，不得直接诱导用户打开。
- 建议操作顺序：**先源码视图通读 → 再切预览**；无法确认编辑器安全策略时，使用隔离环境。
- 不得把凭据、cookie、token 类信息写入任何文件或对话。

## A7 素材请求规则

- agent 自身获取能力有限（**尤其网页抓取**）。凡需要外部材料且首次自行获取尝试失败时，**一律向用户提出请求，由用户获取后提供**，不得自行拼凑、不得凭记忆代替。
- 提出请求时必须一次说清四件事：
  1. **需要什么** —— 规范名 / 章节 / 版本 / 具体锚点；
  2. **为什么需要** —— 对应哪个文件的哪一条用例；
  3. **期望形式** —— 网页另存为文件 / 直接粘贴正文 / 仅提供链接；
  4. **放哪里** —— 建议的落盘路径。
- 用户提供后，按 A4 读回验证，并说明**实际拿到什么、缺什么**，不得默认材料完整。
- **判断标准**：只要「凭记忆写」存在与规范原文产生偏差的风险，就必须先请求材料。
- **禁止行为**：
  - 以「大致记得」「应该是这样」填充规范细节；
  - 材料没到手就先写用例、事后再补；
  - 反复自行尝试抓取失败后仍不请求，直到用户追问。
